# HW1 程式說明

## 1. 程式目的

這支程式會從輸入資料中選出一些欄位，使所有列都至少被其中一個欄位覆蓋。每個欄位有自己的權重，程式依照以下順序比較答案：

1. 選取的欄位數量越少越好。
2. 欄位數量相同時，總權重越小越好。

因此，欄位數量是主要目標，權重是次要目標。程式不會為了降低權重而選取更多欄位。

這是最小集合覆蓋問題（Set Cover）的變形。一般情況下，這類問題的最佳解搜尋在最壞情況需要指數時間。

## 2. 輸入與輸出

### 輸入格式

程式透過命令列參數取得輸入檔案名稱：

```text
HW1.exe input.txt
```

輸入檔內容依序包含：

```text
列數 欄數
每個欄位的權重
列編號 欄位編號
列編號 欄位編號
...
```

每組「列編號 欄位編號」表示該欄位可以覆蓋該列。列與欄的編號都從 1 開始。

例如：

```text
3 3
5 2 4
1 1
1 2
2 2
2 3
3 1
```

代表有 3 列、3 欄；三個欄位的權重分別是 5、2、4。第 1 列可由第 1 或第 2 欄覆蓋，第 2 列可由第 2 或第 3 欄覆蓋，第 3 列可由第 1 欄覆蓋。

### 輸出格式

第一行列出選中的欄位編號，並由小到大排列。第二行列出「欄位數量, 總權重」：

```text
1 2
(2, 7)
```

## 3. 主要資料結構

### `Column`

每個 `Column` 物件保存一個欄位的資訊：

- `id`：欄位編號。
- `weight`：欄位權重。
- `rows`：此欄位可以覆蓋的列編號。

### `Answer`

`Answer` 保存目前找到的最佳解：

- `count`：選取欄位的數量。
- `weight`：這些欄位的總權重。
- `columns`：選中的欄位編號。

一開始將數量與權重設為整數最大值，讓第一個可行解能成為目前最佳解。

### 列與欄的對應

程式以兩種方向保存輸入的覆蓋關係：

- `row_to_columns[i]`：可以覆蓋第 `i` 列的欄位。
- `columns[i].rows`：第 `i` 欄可以覆蓋的列。

前者用來找「只有一個欄位能覆蓋」的列；後者用於搜尋時更新覆蓋狀態。

## 4. 覆蓋狀態的 bitmask 表示法

程式用整數的二進位位元表示哪些列已被覆蓋。第 `r` 個位元代表第 `r` 列：

- 位元是 1：該列已覆蓋。
- 位元是 0：該列尚未覆蓋。

`cover_rows` 會把某欄位覆蓋的列加入目前狀態：

```cpp
mask |= (1LL << row);
```

位元 OR（`|`）會保留原本已覆蓋的列，並把新覆蓋的列標記為 1。這樣比較兩個覆蓋狀態時，只需要比較整數，而不用逐列檢查。

`target` 表示所有列都被覆蓋時的狀態。搜尋中只要 `covered == target`，就代表找到完整覆蓋。

## 5. 前處理

### 5.1 先選必選欄位

如果某一列只有一個欄位能覆蓋，該欄位必定要被選取。程式在搜尋前先找出這些欄位，加入 `chosen`，並更新 `covered`。

若同一個欄位是多列的唯一覆蓋欄位，只會加入一次。

這項處理不會排除任何可能的最佳解：任何完整覆蓋都必須包含該欄位，因此可以直接固定，不必在搜尋中再測試選或不選。

### 5.2 建立候選欄位

程式不把下列欄位放進 `candidates`：

- 已經列為必選的欄位。
- 無法覆蓋任何尚未覆蓋列的欄位。

搜尋只處理仍可能增加覆蓋範圍的欄位，可減少不必要的分支。

### 5.3 排序候選欄位

候選欄位依照以下規則排序：

1. 可覆蓋列數較多的欄位排前面。
2. 覆蓋列數相同時，權重較小的欄位排前面。

排序不會改變可選的欄位組合，也不會改變最佳解的比較規則；它的作用是讓搜尋較早嘗試看起來較有希望的欄位，可能提早找到好的解，讓後續剪枝更有效。

## 6. 分支限界搜尋

`search` 逐一處理候選欄位。對每個欄位，原則上有兩種選擇：

1. 選取目前欄位：欄位數加一、總權重增加，並更新覆蓋狀態。
2. 不選目前欄位：保留目前數量、權重與覆蓋狀態，繼續處理後面的欄位。

每次遞迴都進入下一個欄位，因此同一欄位不會在一個解中被重複選取。`chosen.push_back` 與搜尋後的 `chosen.pop_back` 則用來記錄和還原目前搜尋路徑。

### 6.1 已有完整覆蓋時更新答案

當 `covered == target`，程式把目前的欄位數、總權重和欄位清單存入 `Answer`，再返回上一層繼續尋找可能更好的解。

### 6.2 剪掉欄位數已經過多的分支

若目前選取數量已大於最佳解的欄位數，後續只會再選欄位，不可能讓數量下降，因此這條分支不可能勝出，可以停止搜尋。

### 6.3 剪掉欄位數相同但權重不較好的分支

若目前欄位數已等於最佳解，而目前總權重大於或等於最佳解，任何再加入欄位的結果都會有更多欄位。因此這條分支不可能在「先比欄位數，再比權重」的規則下勝出，可以停止搜尋。

### 6.4 檢查剩餘欄位是否還能完成覆蓋

在不選目前欄位之前，`can_finish` 會把剩餘欄位全部假設為可用，檢查它們是否有機會補齊尚未覆蓋的列。

- 若連全部剩餘欄位都無法覆蓋所有列，就不用進入「不選目前欄位」的分支。
- 若有機會完成，才繼續搜尋。

這是可行性檢查，不代表程式真的會選取所有剩餘欄位。

### 6.5 不選不增加覆蓋範圍的欄位

選入目前欄位前，程式會先比較 `new_covered` 和 `covered`。若兩者相同，表示該欄位沒有覆蓋任何新列，不會進行選取它的分支。

## 7. 如何降低搜尋複雜度

### 7.1 未剪枝時需要搜尋多少組合

令 `m` 為前處理後的候選欄位數。若每個欄位都完整測試「選」和「不選」，可能組合數為：

```text
2^m
```

這是指數成長：候選欄位每增加一個，組合數上限約增加一倍。例如候選欄位有 10 個時有最多 1,024 種選法；有 20 個時則有最多 1,048,576 種選法。

### 7.2 各種技巧如何減少實際搜尋量

- **必選欄位預處理**：不再搜尋已經確定必選的欄位，並立即標記它們覆蓋的列。
- **刪除無用候選欄位**：已選欄位或不能覆蓋新列的欄位不進入搜尋。
- **提早找到較好的解**：先試覆蓋列數多、權重較小的欄位，通常能較早建立較好的目前答案。
- **最佳解界限剪枝**：目前欄位數或權重已不可能勝過最佳解時，立刻返回。
- **剩餘覆蓋可行性檢查**：確定剩餘欄位無法完成覆蓋時，不再搜尋該分支。
- **bitmask**：以位元運算更新及比較覆蓋狀態，避免每次都逐列比較兩個集合。

這些技巧減少實際需要展開的搜尋節點，尤其當必選欄位多、無用欄位多，或很快能找到好的答案時效果較明顯。

### 7.3 漸進時間複雜度

令：

- `n`：輸入列數。
- `p`：輸入欄數。
- `E`：列與欄之間的覆蓋關係數，也就是輸入中的列欄配對數。
- `m`：前處理後的候選欄位數，`m <= p`。

讀取資料和建立對應關係約需 `O(n + p + E)`。目前程式用 `find` 線性檢查欄位是否已選，因此必選欄位去重與候選欄位篩選最壞約需 `O(p(n + p) + E)`；候選欄位排序約需 `O(m log m)` 次欄位比較。

搜尋最壞情況仍可能展開所有選／不選組合。每個搜尋節點的剪枝檢查可能再次掃描部分剩餘欄位，因此保守地看，最壞時間上界可寫成：

```text
O(2^m * E)
```

這是保守的上界；實際執行時間通常會因剪枝而低於此值，但無法保證一定如此。若沒有任何分支能被剪掉，搜尋仍會呈指數成長。因此，這些方法是讓實際搜尋更有效率，並沒有把此問題的最壞時間複雜度變成多項式。

### 7.4 空間複雜度

輸入關係、欄位資料與候選欄位約需 `O(n + p + E)` 記憶體。遞迴深度最多為候選欄位數 `m`，目前選取清單也最多有 `m` 個欄位，因此搜尋額外使用 `O(m)` 的遞迴與路徑空間。

程式使用深度優先搜尋，不會同時保存所有 `2^m` 種組合，所以不需要 `O(2^m)` 的組合表。

## 8. 限制與注意事項

1. **位元遮罩列數限制**：`target` 使用 `1LL << (num_rows + 1)`，並將 bit 0 保留不用。以目前 `long long` 寫法，列數應不超過 61；再大可能產生未定義或錯誤結果。
2. **輸入資料需有效**：程式假設列編號和欄位編號在有效範圍內，且權重和配對資料格式正確；目前沒有逐筆檢查所有輸入欄位。
3. **無可行解時沒有專用訊息**：若某些列完全沒有任何欄位可覆蓋，程式找不到完整解，`Answer` 會保留初始值。使用前應確保輸入存在完整覆蓋，或另行加入無解檢查。
4. **遞迴搜尋仍可能很慢**：當候選欄位很多、剪枝效果有限時，最壞情況仍需要指數時間。
5. **執行參數**：此版本直接使用 `argv[1]` 作為檔案名稱，因此執行時必須提供輸入檔路徑。

## 9. 程式執行流程摘要

1. 從檔案讀取列數、欄數、欄位權重和列欄覆蓋關係。
2. 用 `Column` 和 `row_to_columns` 建立兩種方向的關係資料。
3. 找出只能由單一欄位覆蓋的列，先選入這些必選欄位。
4. 移除已選欄位和不能增加覆蓋範圍的欄位，並排序候選欄位。
5. 使用 bitmask 記錄覆蓋狀態，透過分支限界搜尋候選欄位的選擇組合。
6. 輸出欄位數量最少、且在數量相同時總權重最小的組合。
